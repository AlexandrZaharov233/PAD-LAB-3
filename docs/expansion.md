# Новые функции ParkSlot 1.1

Версия добавляет четыре самостоятельных сервиса к исходным шести. Каждый новый сервис запускается отдельным процессом, имеет собственный том SQLite, настройки, REST API, Swagger, журнал и проверки готовности. Проект по-прежнему запускается на локальном ПК через Docker Compose.

| Сервис | Какие данные и правила ему принадлежат | Как проверить |
| --- | --- | --- |
| Promotion | Промокоды, проценты, периоды, минимум суммы, ограничения по парковке, лимиты и резервы применений | Ввести PARK10 в форме бронирования, сравнить итоговую стоимость и сумму оплаты |
| Waitlist | Заявки на интервалы, порядок очереди, предложения и срок их действия | Занять все места на интервал, подать заявку, освободить одно место и проверить предложение |
| Maintenance | Причины и интервалы работ, состояние синхронизации с календарём | Закрыть место на час, проверить доступность внутри и за пределами этого часа |
| Reporting | Сводки и собственные копии данных, необходимых для отчётов | Провести учебную оплату, затем отменить бронь и сравнить оплаты, возвраты и итог |

## 1. Промокоды

У ParkSlot есть демонстрационный код `PARK10`: скидка 10%, максимум 100 применений. Администратор в разделе **«Промокоды»** создаёт код, задаёт процент, минимум суммы, срок, парковку и лимит. Выключенный или просроченный код не принимается. Округление скидки выполняется вниз до целого бана.

Предпросмотр скидки через `POST /api/promotions/quote` не занимает применение. При создании брони Booking получает актуальный тариф из Parking, сам вычисляет исходную сумму и резервирует применение в Promotion. В брони сохраняются исходная сумма, скидка, код и итог. Payment запрашивает именно итоговую сумму из Booking. Клиент не передаёт цену для оплаты.

Резерв вместе с использованными применениями входит в лимит. Подтверждённая бронь использует применение. При отмене неоплаченной брони или истечении её резерва применение освобождается; возврат по ранее подтверждённой брони лимит не восстанавливает. Если срок резерва истёк и событие ещё не поступило, Promotion уточняет состояние через внутренний API Booking, прежде чем освободить применение.

Повтор создания с тем же ключом и телом не расходует ещё одно применение. При смене цены или других условий сервер повторно проверяет скидку перед созданием брони.

## 2. Лист ожидания

Выберите открытую парковку и будущий интервал, на который нет свободных мест. Войдите в аккаунт и нажмите **«Встать в лист ожидания»**. Раздел **«Лист ожидания»** показывает только ваши заявки. Повторное добавление того же активного интервала возвращает прежнюю заявку.

После отмены или истечения брони, а также после отмены обслуживания Booking публикует `ParkingSlotReleased`. Waitlist проверяет доступность места на **весь** запрошенный интервал. Затем он предлагает его первому подходящему пользователю по времени подачи заявки и публикует `WaitlistOfferCreated`. Notification создаёт сообщение, если у пользователя включены уведомления.

Предложение действует до 10 минут, но не дольше начала выбранного интервала. По кнопке **«Выбрать место»** открывается форма с предложенным местом и датами. Предложение не является бронью: при оформлении Booking ещё раз проверяет место. При отказе или истечении предложения сервис проверяет возможность предложить место следующему. Создание брони пользователя на тот же интервал закрывает его заявку.

## 3. Обслуживание

Войдите администратором. В **«Обслуживание»** выберите парковку, место, даты и причину, нажмите **«Закрыть на этот период»**. Разрешены будущие интервалы от одной минуты до 30 дней.

Maintenance сохраняет план у себя и отправляет внутренний запрос в Booking. Booking хранит блокировку как запись своего календаря и одной транзакцией проверяет пересечения с действующими бронями и другими работами. При одновременном бронировании и закрытии места успешно завершается только одна операция. Если уже есть пересекающаяся бронь, администратор получает отказ и выбирает другое время.

На экране поиска место с пересечением помечено **«ремонт»**. За пределами интервала оно доступно при отсутствии других ограничений. **«Открыть место»** в списке работ отменяет блокировку. При временной недоступности Booking план остаётся в состоянии синхронизации и повторяется в фоне с тем же идентификатором.

## 4. Отчёты

Раздел **«Отчёты»** доступен администратору. Для выбранного периода показываются:

- количество созданных броней с разбивкой по текущим статусам;
- успешные учебные оплаты по дате платежа, возвраты по дате возврата и разница;
- созданные и отменённые брони по парковкам, подтверждённые часы парковки, попадающие в период.

Подтверждённые часы показывают запланированную загрузку по броням. При первом запуске Reporting импортирует сохранённые брони и платежи порциями через внутренние REST API. Новые данные поступают через JetStream. Повторное событие обновляет ту же запись, а старая версия данных не перезаписывает более новую.

## 5. Сквозная демонстрация

1. Администратором создайте парковку **с одним местом**.
2. Запланируйте обслуживание этого места на будущий интервал.
3. Войдите обычным пользователем и найдите парковку на тот же интервал. Подайте заявку в лист ожидания.
4. Администратором откройте место через отмену работ. Пользователю придут предложение и уведомление.
5. Пользователем откройте предложение, добавьте `PARK10`, оформите бронь и проведите учебную оплату.
6. Администратором откройте отчёт за сегодня и сравните сумму с оплатой. После отмены брони проверьте возврат.

Разные аккаунты удобно открыть в обычном и приватном окне браузера. Для смены аккаунта в одном окне используйте кнопку «Выйти». Отчёты и уведомления обновляются после доставки событий; в отчёте нажмите «Обновить отчёт».

Описание запросов доступно в [docs/api.md](api.md) и Swagger каждого сервиса. Для проверки контейнеров выполните `docker compose ps` из папки проекта, а для запуска тестов используйте `check.bat`.
