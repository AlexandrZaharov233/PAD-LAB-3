# Что проверено в комплекте

Проверка выполнена 14 ноября 2026 года. Скрипт [verify-k8s.bat](../verify-k8s.bat) предназначен для полной проверки на Windows после запуска Minikube.

| Проверка | Результат |
|---|---|
| Логика и целостность приложения | 70 тестов прошли на 10 отдельных backend-процессах, Gateway и настоящем NATS JetStream. Последний нативный запуск проверил доставку событий и восстановление; интерфейс проверялся при подготовке исходного комплекта. Подробности в [verification.json](verification.json) |
| Compose | `docker compose config --quiet` прошёл для обычного запуска и профиля `test`; конфигурация содержит 12 основных контейнеров |
| Kubernetes-манифесты | `kubectl kustomize k8s` собрал 39 объектов; каждый прошёл проверку схемы Kubernetes v1.36 |
| API Kubernetes | Изолированный `kube-apiserver` v1.36.0 с etcd принял `apply -k k8s --dry-run=server --validate=strict` и обычный `apply`. Созданы 11 Deployment, 1 StatefulSet, 13 Service, 11 PVC, 2 ConfigMap, namespace и 2 сгенерированных Secret |
| Команда масштабирования | Настоящий API Kubernetes принял `kubectl scale deployment/gateway --replicas=3`; поле `spec.replicas` изменилось на 3 |
| Конфигурация NATS | Настоящий NATS принял конфигурацию из ConfigMap, обработал запрос готовности и сохранил событие JetStream |
| PowerShell | Сценарии запуска и демонстрации проверены синтаксическим анализатором PowerShell |

Изолированный API-сервер проверял регистрацию и обновление объектов. Без узла кластера он не может запустить Pod’ы, выделить реальные тома или проверить распределение сетевого трафика. Эту часть, а также сборку и запуск контейнеров на Windows, выполняют `start-k8s.bat` и `verify-k8s.bat`.
