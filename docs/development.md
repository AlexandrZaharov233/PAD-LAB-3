# Разработка без Docker

Обычный запуск описан в [README](../README.md): `start.bat` для Compose или `start-k8s.bat` для Minikube. Этот раздел предназначен для разработки и воспроизведения проверки в среде без Docker.

## Окружение

Python 3.12, зависимости `requirements-dev.txt`, NATS Server 2.11.8. В тестах проверено окружение, указанное в `verification.json`. Нативный скрипт не скачивает и не устанавливает системные программы автоматически.

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe scripts/configure.py
.venv\Scripts\python.exe -m pytest -q
```

Для запуска реального брокера подготовьте конфигурацию NATS по образцу `infrastructure/nats.conf`, замените переменные авторизации на значения из локального `.env`, задайте адрес `127.0.0.1` и доступный каталог JetStream. Запустите NATS отдельным процессом, затем:

```powershell
.venv\Scripts\python.exe scripts/local.py
```

Скрипт запускает десять самостоятельных сервисов и Gateway. Ctrl+C завершает только его дочерние процессы. БД сохраняются в папке `data`. Порты нативного запуска перечислены ниже; в лабораторной №3 Compose и Minikube используют другие порты.

## Полная автоматическая проверка процессов

`verify_native.py` самостоятельно создаёт временную конфигурацию, запускает настоящий брокер, десять сервисов и Gateway, выполняет тесты и проверки восстановления, затем завершает созданные процессы. Он не использует основную `.env` и не удаляет пользовательские данные.

```powershell
.venv\Scripts\python.exe scripts/verify_native.py --nats C:\Tools\nats-server.exe
```

Проверяются модульные тесты, реальные API-запросы, конкурентное бронирование, доставка уведомлений после остановки потребителя, восстановление outbox после остановки брокера, сохранность брони после перезапуска сервиса и Request ID в логах. Итог записывается в `docs/verification.json`.

Для ручного запуска только E2E на уже работающем приложении:

```powershell
$env:RUN_E2E = '1'
$env:E2E_URL = 'http://127.0.0.1:8080' # нативный запуск
$env:E2E_ADMIN_EMAIL = 'адрес из .env'
$env:E2E_ADMIN_PASSWORD = 'пароль из .env'
.venv\Scripts\python.exe -m pytest -q tests/test_e2e.py
```

## Порты и адреса

Gateway: 8080. Auth: 8011, Profile: 8012, Parking: 8013, Booking: 8014, Payment: 8015, Notification: 8016, Promotion: 8017, Waitlist: 8018, Maintenance: 8019, Reporting: 8020. Нативный брокер: 4222; мониторинг 8222.

При отдельном запуске сервиса установите `PYTHONPATH` на корень проекта и передайте ему публичный JWT-ключ, адрес и учётные данные NATS, путь собственной БД и адреса REST-зависимостей. Только Auth требует закрытый JWT-ключ и параметры первоначального администратора. Конкретные параметры приведены в `docker-compose.yml`.

Воспроизводимая сборка использует зафиксированные прямые зависимости. Для полного закрепления транзитивных зависимостей добавлен `constraints.txt`, сформированный по проверенному окружению. Docker устанавливает зависимости с этим файлом ограничений.
